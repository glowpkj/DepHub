0.1.40 | Steal An Exu: the steal now teleports onto the Exu itself, and there are two new Auto Upgrade toggles. The steal bug was that the Nest is not always on top of the Exu -- the debug log showed distances of 14 to 24 studs on some Nests (the prompt only reaches 6.5), so the server was rejecting the fire even though the local trigger fired. The step now finds the exu in Runtime near the Nest, teleports ONTO its Root (inside range) instead of the Nest, then fires, then returns to the base to validate -- the same for both the Auto Steal Exu toggle and the Steal All button. Both are independently on the Steal An Exu tab. New section "Auto Upgrade" with two toggles: "Auto Upgrade Base" clicks the ClickDetector of your own base sign (PenSign.Board.ClickDetector) and "Auto Upgrade Esteira" clicks the treadmill sign (TreadSign.Board.ClickDetector). Both find YOUR base by the Owner attribute, so they follow you when the base changes, and both keep clicking while on. The debug lines now number the steps 1 to 6 and are still tagged [StealAnExu] in the console and the Debug tab.
0.1.39 | Steal An Exu slowed down and made talkative, because the exus were not getting stolen. The cycle now waits longer at every step: after the teleport onto an exu it lets the prompt settle before firing, after firing it waits longer for the prompt to trigger, and it holds on the base long enough for the game to confirm the stash (1.5s on the Auto Steal Exu toggle, 0.8s on Steal All). Every step prints a tagged line to the console and to the Debug tab -- "[StealAnExu] Nest3 2) prompt achado; dist= ... range= ...", "... 3c) Triggered (ativou) -> true/false" -- so it is visible whether the prompt is found, whether it is in range, whether fireproximityprompt ran, and whether the game actually triggered it. If a step is skipped, the reason is printed too.
0.1.38 | Steal An Exu no longer fights the map. The body floats in place (anchored, zeroed velocity) and clips through everything (noclip) while a run is active, so the teleport stops jamming you inside scenery -- collision and anchoring are put back exactly as they were when you stop. Both the Auto Steal Exu toggle and the Steal All button now use the same cycle: teleport onto the exu, wait for its prompt to be in range, fire it, wait for the prompt to trigger, teleport back to your base, then wait to let the game confirm the stash (1s on the toggle, shorter on Steal All) before moving to the next exu. Steal All is the faster, stronger pass (Terreiro9 to Terreiro1) and also tries the prompt from range before it blinks onto the nest.
0.1.37 | Steal An Exu gets a Steal All button (Farming > Auto Steal). One press clears EVERY exu in the game in a single pass, from Terreiro9 down to Terreiro1, with 0.25s between each. For each exu it tries the Runtime prompt from range first (the prompt's activation distance is widened for the instant it fires, then put back), and blinks the teleport onto the Nest for a second try so it still lands on a game that re-checks distance server-side. When the pass ends you are back exactly where you pressed it (your base). The Auto Steal Exu toggle is untouched and still loops one Terreiro on its own.
0.1.36 | Steal An Exu gets its first feature: Auto Steal Exu. Pick a Terreiro in the panel (Farming > Auto Steal), flip the toggle, and it clears that Terreiro in a loop -- an instant teleport to each Nest, uses the Runtime prompt on the exu that lives there, then back to your base to store it, 0.5s between rounds. Your base is found from the Owner attribute on the pens (matched to your own UserId) instead of a fixed Pen1, so it stays right after a server change and works for whoever runs the script. No position anti-cheat in the game, so the teleport is direct rather than a tween.
0.1.35 | Steal An Exu is recognised by the hub now. It has its own route (place 103076400317371 / universe 10771168447) so it no longer falls into the universal backend, and the backend is a clean skeleton with no features yet -- it loads, publishes its own state and is ready for whatever comes next. Nothing to toggle in the panel while the features are being built. Also: a reload at a game whose backend was added after the first list (Blood Strike, Steal An Egg, Violence District and now Steal An Exu) now tears the previous session down the same way every other backend does.
0.1.27 | The panel is smaller, the icons are the library's own, and the open/close toggle is the library's. The window no longer grows with the screen: RedzLib scaled everything by ViewportSize.Y/450, so on a 1080p screen the panel was multiplied ~2.26x and a 600x420 window rendered at 1356x949 -- almost the whole screen. The scale now uses a fixed reference height (900) clamped to 0.75..1.25, so the panel renders at about its declared size (~1.13x, roughly 678x474 on 1080p) and stays the same size on any screen. Tab and category icons are now names looked up in the library's own icon catalogue (the real RedzLib Icons.lua, 818 names -> asset ids, vendored as src/core/redz-icons.lua) instead of emojis: ask for "swords", "apple" or "rocket" and you get the library's real icon; ask for a name the catalogue does not have and the tab simply has no icon, instead of showing a stray glyph. The open/close key (N) is now bound through the library's own Window:NewMinimizer instead of the shell's hand-rolled listener. The Travel island list is per sea: Sea 1, Sea 2 and Sea 3 have different maps, so the dropdown shows only the destinations of the sea the game reports (ReplicatedStorage.Util.Realm) -- Cafe on Sea 2, Castle on Sea on Sea 3 (also a fixed position), instead of mixing them. Also, the fruit tab drops the two distance sliders: fruit ESP and grab now have unlimited range, with no configurable limit, so a fruit is never ignored just because it is far -- the scan still only does the same cheap existence/validity checks. Skip list and Store keep list are multi-select fruit dropdowns built from the game's own fruit-name list: pick fruits by name, no typing, no duplicates, remove by unchecking, and the choices drive exactly the same skip/keep the old text fields did. Under the hood, three events that never worked now do: Heartbeat (island arrival), RenderStepped (dashboard FPS) and InputBegan (open/close key) were checked with type(x) == "table", but Roblox events are RBXScriptSignal, not tables, so the checks were always false and the connections never happened -- they are now pcall-guarded connects.

New shell primitives AddHStack/AddVStack, exposed as Kit.Row/Kit.Stack, with tests.
